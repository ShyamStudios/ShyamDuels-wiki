Configuration Files

Detailed specifications of variables and settings inside the plugin configuration files.

Main Configuration File (config.yml)

Located at plugins/ShyamDuels/config.yml. This file manages module toggles, world structures, command limitations, and party and duel matchmaking metrics.

Module Toggles

Disable specific sub-modules server-wide:

yamlLicense: ""                    # BuiltByBit license key (injected at build time)
debug: false                    # Verbose display/logging output

server:
  name: Practice Server         # Shown in messages and display configs

World and Arena Configurations

yamlarenas:
  world: Arenas               # Base void world; clone worlds become Arenas1, Arenas2, …
  difficulty: HARD              # Applied to base + clone worlds (HARD for crystal/anchor damage)
  cloning: 0                  # Extra world copies for duel capacity (0 = off; FFA never cloned)
  reset-clones-on-startup: true # Delete and re-clone Arenas1/2/… from base world each boot
  reset-on-startup: true    # Sanitize the base arena world and FAWE-reset template arenas on boot
  build-height-limit-offset: 2 # Blocks/liquids at or above maxY minus this offset are blocked
  reset-queue:
    max-concurrent: 3         # Max simultaneous FAWE arena restorations
    ffa-one-at-a-time: true   # Only one FFA reset at a time (duel resets unaffected)
  clear-entities-on-startup: true # Remove dropped items/non-player entities in loaded worlds
  sanitize-clone-worlds: true # Strip entity data from copied world folders
  gamerules:                  # Applied to base + clone worlds on startup/load (all optional)
    daylight-cycle: false     # freeze the time of day
    weather-cycle: false      # freeze the weather
    mob-spawning: false       # doMobSpawning (passive)
    monster-spawning: false   # hostile monsters
    mob-griefing: true        # Arena explosion handling filters damage; required for supported mob explosions
    show-advancement-messages: false
    locator-bar: false        # player locator HUD
    show-death-messages: false
    natural-regeneration: true
    spawn-phantoms: false
    spawn-patrols: false
    spawn-wandering-traders: false
    spawn-wardens: false
    raids: false              # false = raids disabled
    random-tick-speed: 0      # stop block/crop ticking
    fire-spread: 0            # no fire spread

See the Arena Setup: Arena Cloning guide for how cloning works. Build template arenas only in the base Arenas world, not in Arenas1, Arenas2, or other auto-generated clone worlds.

Arena Instances and Automatic Capacity

Optional individual copies of selected original DUEL arenas in a separate owned void world. Both switches are disabled by default; an update alone does not replace existing cloning or enable expansion. Add this subsection inside your existing arenas: section:

yamlarenas:
  instances:
    enabled: false
    world: ShyamDuelsInstances
    templates: []              # Original arena names, NOT kit names; empty means none
    initial-copies: 2
    max-copies-per-template: 8
    max-total-copies: 128       # Generated reservations only; failed/retired slots also count
    spacing-blocks: 64
    max-concurrent-preparations: 1
    auto-expand:
      enabled: false
      minimum-ready: 1
    overrides: {}

Enabling/disabling, destination world, template membership, and spacing changes require a restart. Capacity/reserve/concurrency changes can use /sd reload-config confirm; lower caps do not delete copies. Read Arena Instances & Automatic Capacity for activation, per-template overrides, commands, backup/recovery rules, and sizing limits.

Lobby World Protection

The lobby location and optional world protection are configured under lobby:. When protect-world is enabled, the plugin disables PvP, mob spawning, mob griefing, and freezes time/weather in the lobby world via gamerules, applied on startup and whenever the lobby world loads. adventure-mode puts players into Adventure mode whenever they are sent to spawn (admins with shyamduels.admin.bypass and Creative/Spectator players are left untouched).

yamllobby:
  world: spawn
  x: 0.0
  # ... y, z, yaw, pitch ...
  adventure-mode: true        # Force Adventure mode in the lobby
  protect-world: true         # Apply the protective gamerules below to the lobby world
  gamerules:                  # Each value is optional and falls back to the shown default
    mob-spawning: false       # doMobSpawning (passive)
    monster-spawning: false   # hostile monsters
    mob-griefing: false       # mobGriefing
    daylight-cycle: false     # freeze the time of day
    weather-cycle: false      # freeze the weather
    show-death-messages: false
    random-tick-speed: 0      # stop block/crop ticking

Portals

Vanilla settings such as allow-nether=false or the portal gamerule apply per world and do not cover every setup (for example lobby or arena worlds made by a world manager). ShyamDuels blocks portals itself for players in its lobby worlds, arena worlds, duels, FFA or spectating. Players in other worlds (survival and so on) are not affected, and shyamduels.admin.bypass ignores the block. The message is general.portal-blocked in lang/messages.yml (empty for none); it is sent at most once every 3 seconds.

yamlportals:
  block-nether: true
  block-end: true
  block-end-gateway: true

Optional Practice-World Isolation

For mixed-gamemode servers only. Default-off; dedicated practice servers do not need to enable it.

yamlworld-isolation:
  enabled: false
  additional-worlds: []
  blocked-message: '<red>ShyamDuels is only available in practice worlds.</red>'

Configured lobby/base arena/numbered clone worlds and ownership-verified instance worlds are included automatically. List other manual practice worlds by exact name in additional-worlds. Changing the enabled mode requires a restart. This is not a per-world inventory store; use and test a separate inventory/game-mode solution before combining survival and practice. See World Isolation for command scope, activity-exit rules, and limitations.

yamlenabled-worlds:

  right-click-duel:

Configure command rules inside matches to block cheating or bypass attempts:

yamlcommand-restrictions:
  allowed:                    # Always permitted (plus admin bypass)
    - leave
    - leavefight
    - spawn
    - spectate
  in-party:                   # Blocked while in a party lobby
    - kiteditor
    - duel
    - ffa
    - spectate
  in-match-global:            # Blocked during any active match
    - kiteditor
    - duel
    - queue
    - play
    - ffa
    - party
  in-duel:
    mode: block-all
    commands: []
  in-ffa:
    mode: block-all
    commands: []
  in-spectate:
    mode: block-all
    commands: []

Queue and Duels

yamlqueue:
  multiple-kits: true         # Allow queuing multiple kits at once
  max-multiple-kits: 3        # Max kits queued at once (minimum 1; values <1 clamp to 1; needs multiple-kits)
  random-queue-enabled: true  # Random kit queue option
  override-conflicting-commands: true # Reroute /queue to ShyamDuels over other plugins
  modes:                      # Disable individual queue sizes
    1v1: true
    2v2: true
    3v3: true
    4v4: true
  types:                      # Queue types players may join
    ranked: true
    unranked: true
  match-found-animation:
    enabled: true
    blindness: true           # Apply blindness for the duration of the match-found animation
    blindness-duration-ticks: 200 # Safety cap (removed early by animation callback; should exceed animation length)
    totem-pop: true           # Client totem-pop on match start (bundles item overlay + particles + sound)
    totem-sound: false        # false suppresses the local vanilla pop sound; custom sound below can replace it
    sound: ""                 # Optional extra sound key; empty = no sound
    sound-volume: 1.0
    sound-pitch: 1.2
    fallback-item: DIAMOND_SWORD  # Item model shown in the pop when a kit has no icon (totem-pop only)

  indicator:
    enabled: true
    height-offset: 1.15       # Vertical offset above nametag passenger mount
    scale: 0.60               # ItemDisplay scale (0.60 balanced with nametag)
    rotation-speed-ticks: 5   # Ticks per 45° step (5 = 2s per full rotation)
    billboard: FIXED          # FIXED (world-space), VERTICAL, or CENTER
    show-to-self: false       # Show indicator to the queued player in F5

duels:
  invite-expiration: 60       # Seconds before duel invites expire
  invite-resend-cooldown: 10  # Seconds before the same sender can re-invite the same player (0 disables)
  start-countdown: 5          # Countdown before round starts
  round-system: BEST_OF       # BEST_OF (majority of rounds) or FIRST_TO (exact win count)
  end-commands: []            # Console commands run when a duel ends
  xp-animation:
    enabled: false           # Client-only XP score/skull effect; server AND client 1.21.11+
  round:
    next-round-delay: 5s      # 0s is supported; shorter pauses stop the cosmetic effect early
    score-chat: true
  match:
    end-delay: 5s             # Final celebration pause, independent of the next-round delay

leavefight:
  delay: 1                      # Teleport delay in seconds after /leavefight (0 disables the delay)

spawn:
  delay: 1                      # Teleport delay for /spawn (falls back to leavefight.delay)

The optional XP animation lasts up to 3.8 seconds and never extends these pauses. It shows the round score, then a skull on the final win; transitions/teleports clean it up early. See XP Round-Win Animation.

queue.types turns ranked or unranked queues off for the whole server, for example a ranked-only server. The turned-off type disappears from the queue menu (the Ranked/Unranked switch only shows when both are on), and /ranked or /unranked with a kit tell the player it is off (queue.type-disabled). Party queues follow the same rule. Direct /duel requests are not queues and are not affected. If both are set to false, unranked stays on and a warning is logged.

Arena World Borders

Per-player, client-side red borders drawn around arenas during duels, FFA, and spectating. They are sent as packets and never modify the real server world border. See Arena Setup: Fake World Borders for the full explanation.

yamlworld-border:
  enabled: true               # Master switch; false sends no arena borders at all
  padding: 0.0                # Extra blocks on every side (0.0 hugs the corner blocks exactly)
  warning-blocks: 0           # Red "approaching border" overlay distance in blocks (0 = off)
  warning-time: 0             # Red warning overlay duration in seconds (0 = off)

world-border-shrink:
  enabled: false              # Timed per-duel border shrink (PacketWorldBorderManager + MatchBorderShrinkSession)
  kits: ["*"]                 # Kit filter ("*" = all kits)
  interval: 1m                # Shrink step interval (ms/s/m/h/d/t units, bare number = seconds)
  shrink:
    blocks-per-interval: 10.0
    duration: null             # Optional lerp duration (same units); null = instant step
  minimum-distance-from-center: 5.0  # Minimum radius; minimum diameter = 2x this value
  sound:
    enabled: false            # One warning per actual shrink step, active fighters only
    sound: minecraft:block.note_block.pling
    volume: 1.0               # 0-4
    pitch: 1.0                # 0.5-2
  damage:
    enabled: true
    amount: 2.0
    interval: 1s
    buffer-blocks: 0.0

Both border switches and the kit filter must allow shrinking; enabling audio alone does not start it. Use namespaced sound keys, not Bukkit enum names. Each actual size reduction warns active fighters once, including the final clamped step, but not spectators/lobby players. Invalid sound settings disable only audio. Reload with /sd reload-config confirm; existing shrink sessions are not restarted. See Border Shrinking.

Advancements

Challenge/achievement subsystem (AdvancementManager, 36 trigger types). Full key reference lives in advancement.yml - settings, defaults, per-category tabs, per-advancement triggers/conditions/rewards. See the Advancements guide for every key, all trigger and condition types, and a step-by-step example. Key commands: /advancements (aliases /adv, /achievements, /sdadv), admin grant/revoke/reset/resetall/reload (shyamduels.advancements.admin). Event: AdvancementGrantEvent (see Events Reference). Persistence: player_advancements table.

GUI Mode (Normal vs Dialog)

Menu routing is controlled by gui.mode in config.yml (NORMAL = FastInv inventories, DIALOG = Paper 1.21.7+ dialogs from dialog-menus/*.yml, 63 files). Dialog clicks are debounced (150ms) with single-use 5-minute callbacks. Every dialog menu, the Back button and the kit descriptions are described on Dialog Menus. Small texts of the older dialogs (titles, tooltips, shared buttons) are in dialog-menus/menu-texts.yml, see Texts of the other menus.

The dialog queue menu (dialog-menus/queue.yml) opens on Unranked for players who have never switched, then remembers their last choice. Ranked is 1v1 only, so the 1v1-4v4 row shows under Unranked only. Custom kits stay out of Ranked unless dialog-queue-menu.custom-kits-in-ranked: true.

Hover texts in the queue and tier dialogs: kit and category descriptions come from dialog-menus/kit-info.yml. A kit or category left out there uses the lore already set on its icon item, so most servers need no setup. The kit icon shows the player's tier, points and queue size; the progress bar under a ranked kit tells the player the next step towards a tier test.

Pause Menu Links

pause-links adds buttons to the client's pause menu under Server Links. Each entry has a MiniMessage name and an http/https url. New installs and upgraded servers get the ShyamStudio Discord and BuiltByBit links enabled; set enabled: false to hide them. Changes apply on /shyamduels reload-config confirm, and links added by the server or other plugins are left alone.

pause-links:
  enabled: true
  links:
    - name: "<#5865F2>Discord"
      url: "https://discord.gg/r6XJyfzhdT"
    - name: "<#FFAA00>BuiltByBit"
      url: "https://builtbybit.com/shyamstudio"

Match History

Every finished duel is saved with each player's result, Elo and tier rating change, combat counters, final health and final inventory, and can be browsed with /matchhistory [player]. Full guide: Match History.

match-history:
  enabled: true
  keep-days: 30          # 0 keeps matches forever
  save-inventories: true # about 1-4 KB per player per match

Texts: dialog-menus/match-history.yml (dialog mode) and menus/match-history.yml (inventory mode).

Friends

yamlfriends:
  # How long a pending friend request stays valid before it is auto-removed, in seconds.
  # Set to 0 (or negative) to disable expiry and keep requests forever.
  request-expiry-seconds: 300

Expired requests are cleaned up by a background task and also pruned whenever a player's requests are read, so a request disappears once request-expiry-seconds has passed.

Combat Death Drops and Kill Refill

combat.death-drops.ffa and combat.death-drops.duels are independent. Enable only the mode where you want loot. Real deaths honour keepInventory; virtual practice deaths transfer the practice loadout. XP drops remain disabled. Bridge portal returns are not loot-producing deaths.

Death loot expires after its configured lifetime, or earlier on round/reset cleanup or normal despawn. This does not clear unrelated ground items or run a full-world scan every tick. Picked-up items become normal inventory items. There is a 10,000 active/pending death-drop safety cap; excess is discarded with a warning. Real item entities still cost resources, so test representative load before enabling broadly.

Older configurations migrate missing mode switches from the inverse of combat.anti-death-drops, preserving an existing loot choice. Once mode switches exist, edit those instead of the legacy key. Reload affects new loot only; existing deadlines remain.

kill-regen is separate from loot: use kill-regen.ffa: false to disable FFA kill refill/regeneration without changing duel settings, or the master enabled: false to disable it globally. This is the existing combined refill/regeneration option, not separate health-only and inventory-only controls. See FFA Death Drops and Kill Refill.

Shulker Lore Previews

  separator: " "             # Separator between sprites on one line
  max-sprites-per-line: 9    # Sprites per lore line (1-9, 27 slots total over 3 rows)
  lore-position: BOTTOM      # BOTTOM or TOP (where preview lines are inserted)
  header: ""                 # Optional line above the preview
  footer: ""                 # Optional line below the preview
  white-sprite: true         # Use white sprite variant
  empty-slot: "<dark_gray>?</dark_gray>"  # Placeholder for empty slots
  sprite-overrides: {}       # Per-material sprite replacements
  potion-colors: {}          # Per-potion color overrides (default water: #385DC6)

Golden Head Item Identity
Keep golden-head.item.id set to minecraft:honey_bottle to retain the intended consumable behaviour. The Golden Head appearance is supplied by item.texture-value; item.texture-url is optional reference data.

Golden head, totem practice, and door animation are toggled via modules.*, not separate enabled keys on those sections.

Tab List and Scoreboard

Tab headers/footers and scoreboard layouts are configured in separate files:

  • plugins/ShyamDuels/tab/display.yml - tab list header, footer, and name formats
  • plugins/ShyamDuels/tab/scoreboard.yml - in-match and lobby scoreboards
  • plugins/ShyamDuels/tab/animations.yml - scrolling tab animations

Reload tab config with /tab reload. Players toggle tab/scoreboard visibility in /settings.

In tab/scoreboard.yml, scoreboard.async-placeholders: true (default) resolves PlaceholderAPI off the main thread for performance. Set it to false only if a PlaceholderAPI expansion you use is not thread-safe and errors on the scoreboard.

Other tab/scoreboard.yml keys: scoreboard.update-time, scoreboard.lobby-update-time, scoreboard.max-updates-per-tick, scoreboard.title, scoreboard.disabled-worlds, scoreboard.teleport-update, scoreboard.party-addition, scoreboard.enderpearl-cooldown-*. Nametags and Below-Name Health System

Nametags and above-head health displays are configured in tab/display.yml under nametags: and belowname-objective:.

ShyamDuels v2.0+ supports both modern background-free TextDisplay entities (1.19.4+) and legacy vanilla scoreboard teams:

yaml# tab/display.yml
nametags:
  enabled: true
  # Display mode:
  #   text-display -> Modern (1.19.4+), background-free nametags with crisp text drop shadows (Recommended)
  #   scoreboard   -> Classic vanilla scoreboard teams (has client-side dark translucent background)
  mode: text-display

  # Settings for text-display mode:
  # background-color: 'transparent' (no background box), or hex '#RRGGBB' / '#AARRGGBB', or 'default'
  background-color: transparent
  # Enables crisp text drop shadows for contrast against all blocks and skies
  text-shadow: true
  # Vertical offset above player's head (default: 0.25)
  height-offset: 0.25
  # Whether nametag is visible through solid blocks
  see-through: false
  # Show players their own nametag (third-person view). Off by default.
  self-visible: false

  # Text before player name above head
  tagprefix: '%luckperms_prefix%'
  tagsuffix: ''
  collision: never
  respect-npcs: true

belowname-objective:
  enabled: true
  # In text-display mode, this is automatically merged as Line 2 of the background-free display
  fancy-value: '<#FFFA45>%shyamduels_rank% &r» <#FF780C>%shyamduels_elo% ELO'
  per-world:
    Arenas:
      fancy-value: '<#FF1D54>❤ %player_health_rounded% | <#FFFA45>❤ %player_golden_health%'
      value: '%player_health_rounded%'

In arena worlds the red heart is real HP. After a golden apple or golden head, absorption is shown as a gold heart (for example ❤ 18.0 | ❤ 4.0). Both values are shown to one decimal place. The gold half is omitted when absorption is 0. %player_health_rounded% is HP only; %player_golden_health% is the absorption number.

Highlights of TextDisplay Mode:

  • Background-Free: Removes the dark rectangular background box rendered by vanilla Minecraft clients.
  • Multi-line Integration: Combines player rank/prefix/name and below-name health (❤ 21.8) in a single unified display.
  • Client-Side Interpolation: Passenger mounting ensures 0-jitter, 100% smooth positioning matching client FPS.
  • First-Person Protection: Automatically hidden from the player themselves to keep the 1st-person screen clear during combat.

Custom Item Icons (Custom Model Data & Nexo)

Every item entry in a menu or item config supports two optional fields for swapping the vanilla icon for a resource-pack model or a Nexo custom item. Both sit alongside the normal material, name and lore keys:

yamlsome-item:
  slot: 11
  material: DIAMOND_SWORD
  # Optional custom icon (pick one):
  custom-model-data: 1001     # Applies a CustomModelData value to the vanilla material
  # nexo: my_custom_icon      # OR pull the icon (and its model) from a Nexo item id
  name: "&b&lRANKED QUEUE"
  lore:
    - "&7Click to queue"

Custom Model Data

custom-model-data: <int> stamps a CustomModelData value onto the configured material, so a resource pack can render a custom texture/model for that slot. It is only applied when the value is greater than 0; leave it out (or set 0) to keep the default look. The material must still be a valid Minecraft item.

Item Model

On modern Paper versions, item-model: <namespace:key> applies Minecraft's Item Model component to a vanilla material. This is useful when a resource pack supplies a model without relying on CustomModelData:

yamlsome-item:
  material: HONEY_BOTTLE
  item-model: "minecraft:player_head"

The item remains the configured material; the model changes only its appearance.

Nexo Items

Nexo is an optional soft-dependency. When it is installed, you can render any Nexo custom item as a menu icon using either form:

yaml# Explicit field:
nexo: my_custom_icon

# Or as a material shorthand:
material: "nexo:my_custom_icon"

The Nexo item id (with its own model) takes priority. If Nexo is not installed, or the id does not exist, ShyamDuels falls back to the vanilla material plus any custom-model-data, so menus never break on servers without Nexo. On startup the console logs Nexo hook: enabled when the integration is active.

Precedence
A Nexo id (from the nexo: field or a nexo: material) is resolved first. Only when no Nexo item is found does the vanilla material + custom-model-data apply. You don't need Nexo installed to use custom-model-data.

Database Connection Settings (database.yml)

Database settings are stored in plugins/ShyamDuels/database.yml as a separate editable file. On startup and when you run /shyamduels reload-config, the plugin merges this file into the runtime config under the database.* prefix (e.g. database.type, database.performance.io-threads). Edit database.yml on disk; you do not need a database: block inside config.yml.

yaml# ==============================================================================
# Database Configuration (plugins/ShyamDuels/database.yml)
# ==============================================================================

type: "SQLITE"                  # SQLITE or MYSQL

# Performance settings (tuned for big servers: 300+ players)

sqlite:
  directory: data
  arenas-file: arenas.db      # Local SQLite database files
  kits-file: kits.db
  stats-file: stats.db

mysql:
  host: localhost
  port: 3306
  database: shyamduels
  username: root
  password: ""
  use-ssl: false
  maximum-pool-size: 30       # HikariCP max connections (30 with 10 idle recommended for 400-500 CCU)
  minimum-idle: 10            # Minimum idle connections kept ready
  connection-timeout-ms: 5000 # Max wait for a connection from the pool
  max-lifetime-ms: 1800000    # Max lifetime of a pooled connection (30m)
  idle-timeout-ms: 600000     # Time an idle connection stays in pool (10m)

# Performance settings (tuned for high CCU servers: 400-500+ players)
performance:
  compute-threads: 4          # Scoreboard/Tab diffing & MiniMessage parsing workers (auto: clamp(2,16,cores/2))
  io-threads: 8               # DB queries, GeoIP & file I/O workers (auto: clamp(4,32,cores))
  auto-detect-threads: true   # Auto-detect CPU cores (Pterodactyl/Docker aware) and adjust both pools
  autosave-minutes: 5         # Batch-save all online players' stats every N minutes (0 = off).
                              # Saves everyone in one transaction; limits crash loss to a few minutes.
Scaling to 300+ players
For high player counts, use MySQL (SQLite serializes all writes through a single connection by design). Raise maximum-pool-size / minimum-idle and performance.io-threads together so concurrent queries have both connections and worker threads available. The performance block lives in database.yml and is read under the database. prefix internally. When auto-detect-threads is true, thread counts are derived from detected cores.

Tier, match history and preference tables

Created automatically on SQLite and MySQL in the stats database:

  • tier_profiles: one row per player and kit with tier rating, bars, tier and test history (Tiers).
  • match_history and match_history_players: saved matches and each player's side, including the inventory (Match History).
  • player_preferences: per-player menu choices such as queue favourites and Keep Queuing (Dialog Menus).

ELO and Ranks Database (ranks.yml)

Manages matchmaking ranges and calculations:

yamlelo:
  rank-system: true           # Enable rank progressions
  enabled: true
  custom-kits: false          # Award Win/Loss (and ELO) for custom-kit-system fights.
                              # Official kits (Crystal Sea, Anchor Sea, ...) always count.
  match-types:                # When false, that match type records neither ELO nor Win/Loss.
    duel: true                # Kill/Death still update for every finished match.
    queue: true
    party: false
    party-vs-party: false
    party-split: false
    team-battle: false
    party-ffa: false
    ffa: false
    rematch: false
  starting-elo: 1000          # Base ELO rating for new players
  min-elo: 0                  # Floor a player's ELO can drop to
  base-gain: 25               # ELO added on an even-matchup win (default 25 in EloSettings.java)
  base-loss: 20               # ELO deducted on an even-matchup loss
  kill-gain: 5                # Bonus ELO added per kill

  # Opponent-relative (true Elo) scaling. Beating a much weaker opponent gives almost nothing;
  # beating a stronger one gives more. Set false for flat base-gain / base-loss.
  opponent-based: true
  min-gain: 1                 # Floor for a win (token amount vs far-weaker players)
  max-gain: 40                # Cap for a win (vs far-stronger players)
  min-loss: 1                 # Floor for a loss
  max-loss: 40                # Cap for a loss (vs far-weaker players / prevents extreme swings)

  anti-farm:
    enabled: true             # Block ELO farming exploits
    cooldown-hours: 2         # Cooldown before the same opponent yields ELO again
    max-wins-per-opponent: 5  # Max wins against the same player in cooldown period
    block-same-ip: true       # Block ELO gains between matching IP addresses

  progress-bar:               # %shyamduels_elo_bar% / %shyamduels_elo_progressbar%
    length: 10
    completed-symbol: "|"
    uncompleted-symbol: "|"
    completed-color: "<#00FF88>"
    uncompleted-color: "<#555555>"

Each rank under elo.ranks.* defines name, a colored display tag, an ELO range (min-elo/max-elo) and a loss-multiplier. See ELO & Ranks for the full ladder.

Country Flags & Player Heads Cache

Country display powers /countryflags, tab/nametag flag prefixes, and the %shyamduels_country* placeholders (see the Country Flags guide for the full list of supported countries). It resolves player countries from a MaxMind GeoLite2-Country database:

yamlcountry:
  enabled: true               # Master toggle for the country feature
  update-on-join: true        # Re-check MaxMind on join; persists only when the ISO code changed.
                              # Manual /country flag selections are never overwritten.
  maxmind:
    database: "GeoLite2-Country.mmdb"  # Local file (plugin data folder unless absolute)
    auto-download: true       # Download the database automatically when missing/expired
    download-url: "https://github.com/P3TERX/GeoLite.mmdb/raw/download/GeoLite2-Country.mmdb"

The player's real client IP is taken from Paper's connection address (works behind Velocity/Bungee when Velocity modern forwarding is configured correctly); otherwise it falls back to Player#getAddress(). Without correct proxy forwarding, MaxMind may resolve the proxy host's country instead of the player's.

Player head textures (used by tab lists, scoreboards, and bracket GUIs) are cached with optional Mojang refresh:

yamlheads:
  mojang-enabled: true        # Query Mojang for skin textures
  mojang-interval-ms: 1400    # Rate limit between Mojang requests
  http-timeout-ms: 1500
  positive-ttl-ms: 2592000000 # Successful lookups cached for ~30 days
  failure-ttl-ms: 900000      # Failed lookups retried after ~15 minutes
  max-entries: 20000          # In-memory cache ceiling
  disk-save-debounce-ms: 15000 # Debounce for flushing the disk cache
