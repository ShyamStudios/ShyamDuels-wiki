Optional Practice-World Isolation

Limit practice commands and gameplay/display handling to the selected practice worlds when sharing a server with another gamemode.

Disabled by default
Existing dedicated practice servers do not need this mode. Updating the JAR does not enable it. Keep world-isolation.enabled: false unless you intentionally run practice alongside other worlds and have tested that arrangement.

Configuration

Merge this section into plugins/ShyamDuels/config.yml. This example shows shipped defaults:

yamlworld-isolation:
  enabled: false
  additional-worlds: []
  blocked-message: '<red>ShyamDuels is only available in practice worlds.</red>'

When enabled, the practice-world set includes:

  • Your configured lobby worlds.
  • The configured arenas.world and its recognised numbered clone worlds.
  • An ownership-verified instance world loaded by the arena-instance system.
  • Exact names listed in world-isolation.additional-worlds.

Additional names are case-insensitive, with no wildcard/prefix matching. An empty additional list does not exclude the lobby or arena worlds. If a manually registered arena is in a separate custom world, include that world explicitly.

The older enabled-worlds.kit-editor and enabled-worlds.right-click-duel settings still apply to their respective features; they are not substitutes for whole-plugin world isolation.

What Changes When Enabled?

  • Player execution and completion of ShyamDuels-owned commands are blocked outside practice worlds, including aliases. Console administration remains available. Commands owned by unrelated plugins are not blanket-blocked.
  • Practice admission, item grants, owned GUIs, and display handling check the world policy. ShyamDuels removes its own scoreboard/tab/nametag views when a player leaves the allowed scope.
  • Player data loading, persistence, and disconnect cleanup still run; exclusion is not permission to skip saves.
  • Players must leave queues, matches, FFA, spectating, parties, tournaments, editors, kit rooms, and totem practice through their normal commands before teleporting to an unrelated world.
  • The embedded advancement integration does not install its server-wide vanilla-suppression hook when isolation mode is selected at startup.

Normal practice-to-practice teleports, such as arena-to-lobby returns, remain allowed. This is not a sandbox against another plugin deliberately bypassing Bukkit events.

Not a Per-World Inventory System

Protect survival inventories separately
ShyamDuels does not save and restore a separate survival inventory or game mode for each world. Entering the practice lobby can intentionally give practice items. Use and test a compatible per-world inventory/game-mode solution before enabling this on a mixed survival/practice server.

The option also does not guess or undo gamerules previously changed by another plugin or an older configuration. Review the effective gamerules in your non-practice worlds and restore the values you intend.

Safe Activation

  1. Back up the server and test the arrangement on a copy first.
  2. Verify lobby/arena names and list any additional manual practice worlds.
  3. Set world-isolation.enabled: true and restart. Changing this switch requires a restart for startup-only integrations to use the selected mode.
  4. Test practice entry/exit with your inventory plugin: survival inventory, game mode, sleeping, vanilla advancements, command aliases, menus, tab, scoreboard, and normal duel returns.
  5. Leave all practice activities before testing an external-world teleport. A rejection during an owned activity is intentional.

While the enabled mode stays unchanged, world-list/message edits can use /sd reload-config confirm. Do not use the server-wide /reload. To disable isolation, set the switch to false and restart.
